# First team assignment: plan and prepare one working lesson

## Objective

Prepare the team to build one lesson from the SetuAI textbook, from reading through quiz feedback and saved progress.

Suggested response window: within 48 hours after Agastya shares the kickoff with the team. No calendar deadline has been imposed.

## Everyone's first action

Reply on the kickoff issue with:

- GitHub username.
- Preferred work: frontend, backend, UI/UX, content, testing, or a combination.
- Technologies you can use independently and those you are learning.
- Available hours for the coming week.
- One task you would like to own or support.
- Whether you can review someone else's work and whether you need Git/GitHub help.

Do not include phone numbers, private email addresses, passwords, or other personal data in this public repository.

## How we divide work before appointing leads

Agastya confirms one owner per issue and a peer reviewer. Others can support that owner. Task ownership is temporary; it does not imply a leadership appointment. Match assignments to availability and skills, and pair less experienced members with experienced members.

Do not have all 11 people edit the same setup files. Select one setup owner. Other members can prepare content, design screens, review the data contract, and define test scenarios in parallel.

## Order of work

1. Agastya selects one textbook excerpt and confirms what may be stored publicly.
2. Agree on the learner audience, learning objectives, and required behavior.
3. Design sketches and a technical proposal can proceed in parallel using that scope.
4. Agree on the content/data contract and choose the stack before implementation.
5. One owner scaffolds the application. A second member verifies the setup instructions on a fresh checkout.
6. Divide implementation into small issues with owners and reviewers.
7. Connect frontend and backend early and demonstrate the whole learner journey.

Use sample data that matches the agreed contract while the backend is being built.

## Planning assignment is complete when

- [ ] Members have shared skills and availability.
- [ ] One lesson and its learning objectives are approved.
- [ ] Mobile and desktop sketches cover lesson, quiz, results, and returning progress.
- [ ] A short technical decision records the stack, storage, and identity approach.
- [ ] The shared data contract has examples and failure behavior.
- [ ] The starter application runs using the README instructions on two members' machines.
- [ ] Implementation issues have an owner, reviewer, dependencies, and acceptance criteria.

## Weekly routine

Start of week: agree on one demonstrable outcome and realistic task commitments.
During work: update the issue with completed work, next action, and blockers. Raise blockers promptly.
End of week: demonstrate working behavior, record defects, and choose the next outcome.

A completed implementation task is reviewed, merged, demonstrated in the agreed test environment, and meets its acceptance criteria. Commit counts are not a performance target.
